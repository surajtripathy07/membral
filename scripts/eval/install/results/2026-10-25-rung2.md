# Install, rung two: `membral up` with no Docker

Date: 2026-10-25. Box 1.4 of `docs/goals/2026-10-25_beyond-claude-mem_goal.md` (Lever 1).
Subject: branch `beyond-l1-docker-free` at `f35c4c6b` (after the kernel-held store lock merge). Compare with
`2026-10-25-baseline.md` (the Docker path: about 14 commands, about 3.1 machine minutes, no non-empty search).

## Machine

Same Mac as the baseline (Apple M1 Max, 32 GB, Node v26.8.1). Scratch `$HOME`, a stub `launchctl`, `DOCKER_CONFIG`
pointing at the real Docker config dir. `PATH` was cut to a stub dir (stub `launchctl`, a `node` symlink) plus the
system dirs `/usr/bin:/bin:/usr/sbin:/sbin`. `command -v docker` and `command -v claude` both printed nothing, so
Docker is absent and extraction is off (the `claude` provider needs `claude` on `PATH`). Port 41873. The
`nomic-embed-text-v1.5` ONNX model was not on disk: the server downloaded it into `$HOME/.membral/models` on first use.
The build (`npm run build:local-server`) and the CLI build ran before the timed steps.

## memory_search evidence

- `tools/list`: **10 tools** (search_conversations, get_conversation, list_recent_conversations, list_code_projects,
  get_code_session, memory_search, memory_recall, memory_get, memory_resolve, session_summary).
- Extraction was off, so the record path used was `membral import claude-mem --db` on the fixture, after importing four
  claude-code fixture sessions named to match the fixture's session ids (a bare import with no sessions inserts nothing:
  "no matching Membral session: 10").
- `memory_search` with query `queue` returned 2 records. First record: kind `learning`, source `claude-mem`,
  text "Retry queue loses jobs on restart: The retry queue drops jobs when the worker restarts before the ack is
  written." (unverified, confidence 0.5). Second: kind `decision`, "Ack before dequeue: Switched the worker to write the
  ack row before removing the job from the queue." Queries "ack before dequeue" and "docs" also returned records.
- Timing from the server log: first search `embed_ms` 54287 (includes the one-time model download) with `rpc_ms` 14;
  later searches `embed_ms` 22 and 13, `rpc_ms` 17 and 8.
- The response notes "no calibrated raw-unit floors for this embedding model" for family
  `nomic-embed-text-v1.5-onnx-q8`: the vector step is skipped and raw excerpts are not served. Records come back
  through the lexical path.

## Footprint (after the embedding model loaded)

- Server process (`next-server`): RSS 1,340,336 KB (about 1.28 GiB) after the first search, 1,331,616 KB after three.
- Data dir `local/pgdata`: 64 MB (4 fixture sessions, 10 imported records, plus the migrated schema).
- Model cache `models/`: 145 MB. Whole scratch `.membral`: 209 MB.

## Not done, and why

- Extraction from the sessions: not run. `claude` is not on the cut `PATH` and the scratch HOME has no login, and no
  paid API was allowed. So the fixture sessions produced no extracted records; the claude-mem import was the
  no-LLM path. The baseline's retired-at-creation record problem was therefore not re-tested.
- Migrations applied: the count is not printed by `up`, the server log or `status`; I did not open the data dir
  directly. A second `up` reaching ready in 3 s with no "(created)" user is indirect evidence only.
- Not measured: a 10k-row store, the scheduled ANALYZE, the 2 s slow-request log, the sweep job (launchd was stubbed),
  `--foreground`, and `membral logs`.
- The first-search download of the embedding model needs network access (about 145 MB). The brief expected the
  model to be local; this is the product's own behaviour on first use and is a cost on a clean machine.
- The `up` output prints the generated local password once, in clear.
